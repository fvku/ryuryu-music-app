#### A1 本文の書体（最も目立つ差）

- 実物の本文は**字高（キャップハイト）21px・x高15px**。現行は24〜25px・18pxで、**15〜19%大きい**。
- W36・W37の欧文9行を総当たりで照合し、**Oswald 400・26px・字間+5%** で決まった。
  幅は9行中8行が±0px、残る1行も+1px。字高は全行で一致し、塗りの差は+1.6%。
  | 候補 | 幅の誤差 | 塗りの誤差 | 字高 |
  | --- | --- | --- | --- |
  | **400・26px・+5%** | **0.11%** | **+1.6%** | **21px（一致）** |
  | 350・26px・+6% | 0.44% | −12.4% | 21px |
  | 450・26px・+3% | 1.68% | +13.4% | 21px |
  | 現行 300・31px・0 | 1〜3% | ほぼ一致 | 24〜25px |
- **2026-09-14の誤推定の原因**：幅と塗りの量だけで照合し、字高を見ていなかった。
  「Light 31px・字間0」と「Regular 26px・字間+5%」は、幅も塗りの量もほぼ同じになる。
  2026-09-08の「Regular 29px」も同じ理由で外れていた。
- 和文（W37の7行）：Noto Sans JP・26px・字間+5%なら、幅は全行±1.5px以内で一致する。
  塗りの量は400で+4〜5%、350で−1〜−6%だった。

#### A2 行送り

- 実物W37（28行）は、欧文の21行でベースラインが**31.0px刻み**で完全に等間隔だった（249→869）。
  W36（30行）は29.0px刻みだった。
- 両週とも次の式で±0.3px以内に収まる。**上端を固定し、行送りは整数**という規則になる。
  ```
  L = floor(870 / 行数)               // W36: 870/30 = 29、W37: 870/28 = 31.07 → 31
  baseline_i = 222 + L/2 + 11.7 + i·L   // 11.7 = Oswald 26pxの(ascent − descent)/2（119/29 @100px）
  ```
  Figmaの「行の高さ」の中で字面を上下中央に置く組み方と同じ形になる。
- 現行の`layoutFor(n)`は、先頭を248.5、末尾を1089.5に固定して均等割りしている。
  W37では行送りが31.15pxになり、末尾が3.5px下へずれる。**行数が少ない週ほどずれが大きい。**
  たとえば20行の週では、先頭が7px上、末尾が17px下になる。
- 根拠は2週分しかない。`floor`か四捨五入か、Kohei個人の手調整かは§4-1で確認する。

#### A3 「∞」

- Google Fontsの標準サブセット（latin／latin-extなど）には**U+221Eが含まれない**。そのためOswaldの∞が読み込まれず、
  スタックにある次の書体（Noto Sans JP）で描かれていた。
- `css2?family=Oswald&text=∞`で取得するとOswaldの∞が含まれ、「Ow ∞」の幅は103.8pxになった（実物103.5px）。

#### A4 字間≠0でカーニングが消える

- `TextEngine.prepare()`は、字間が0以外のとき1文字ずつ`measureText(ch)`で測って描く。そのため
  **「Ty」のようなペアカーニングが丸ごと消える**。
- 「Tyber」は実物も字間−2%で、カーニングを効かせた−2%なら99.0px（実物98.5px）になる。現行はカーニングが消えて102.0px。
- 同じ経路はMonthly／Japanの作品名でも使われ、字間を0以外にした作品すべてに影響する。

## 3. 修正方針

### 3.1 描画（Claude Code）

**優先・高**

1. **A1 本文の書体**：`Layout.WEEKLY.OTHERS.TYPE.body`を`weight: 400, size: 26, tracking: 0.05`にする。
   - 和文はスタックの`Noto Sans JP`に400を要求し、Oswaldとウェイトを揃える。350のほうが塗りは近いので、
     見比べてから決める。
   - `drawWeeklyOthers()`は`TextEngine.drawSingle()`へ仕様をそのまま渡す。したがって`linesOf()`の
     「字間の上書き」の罠（design §6.1）は通らない。字間が実際に効くことを描画で確認する。
   - `weekly-weight-check.html`の判定に**字高**を加え、W36・W37の欧文9行と和文7行を回帰として固定する。
     これで同じ誤推定を二度と通さない。
2. **A2 行送り**：`Layout.WEEKLY.OTHERS.layoutFor(n)`を§2 A2の式（上端222基準、`L = floor(870/n)`）へ置き換える。
   - `BODY.ASCENT／DESCENT`は廃止する。`BODY.BOX`はクリック判定が使うので残す。
   - `fits(n)`の下限（`MIN_LEAD`）は§4-2の回答で決める。26pxまで許すなら33行まで入る。
   - `app/generator/hit-test.ts`は`layoutFor()`の戻り値だけを使うので、自動で追従する。
     ただし行の選択を「ベースライン±行送り/2」で切っているため、字の上端付近をクリックすると1行上が選ばれる。
     これは既存の癖なので、ついでに字面の中心（ベースラインの約10px上）を基準に直す。

**優先・中**

3. **A3 「∞」**：`fonts.mjs`に、Oswaldの記号グリフを`text=`指定で取る補助の読み込みを加える
   （∞のほか † ★ ♡ ← → など、作品名に出る記号をまとめて取る）。
   - あわせてRMの作品名・アーティスト名から、Oswaldの標準サブセットに無い文字を洗い出す。
   - Oswaldの全グリフをセルフホストする案もある。Google Fontsの`text=`は文字列ごとに別ファイルになるので、
     記号を固定の一覧で取るほうが扱いやすい。
4. **A4 カーニング**：`TextEngine.prepare()`で、1文字ごとの送り幅を
   「先頭からの累積幅の差（`measureText(先頭〜i文字目) − measureText(先頭〜i−1文字目)`）」で求める。
   これで字間があってもペアカーニングを保てる。
   - **Monthly／Japanの字間≠0の作品名も見た目が変わる**ので、Monthlyの実物でも回帰を確認する。
   - クリック位置の計算（`hit-test.ts`の文字位置）が同じ送り幅を使っているか確認する。
5. **A5 表紙の帯**：自動判定を保守的にする。
   - (a) 確信度0.7未満は採用しない。
   - (b) 0.7以上の顔が帯の幅より広く散らばっていれば、集合写真とみなして中央にする。
   - (c) 顔の中心が中央の窓の内側（0.4〜0.6）なら中央のまま。

   W36・W37の10枚では、W37は5/5、W36は4/5が実物と同じ判断になる（Dizzee Rascalだけ手で直す）。
   寄せた場合の残差は24〜34pxで、顔は帯の中に収まる。
   **自動判定は10枚に合わせた規則にすぎないので、手動の微調整（`docs/codex-generator-handoff.md`で相談済み）を
   Codexへ優先して依頼する。** なお、B2で2000pxのジャケットへ差し替えると検出結果も変わるため、判定の確認は差し替え後に行う。

## 4. Koheiへの確認事項

1. **Other Releasesの行送りはFigmaでどう決めているか。** 「行の高さ＝floor(870÷行数)」で2週分は説明できる。
   W35など別の週の実物があれば、それでも検算したい。
2. **行数の上限**：行送りを文字サイズ（26px）まで詰めてよいか。よければ33行まで入る（現行は30行まで）。
3. **作品名の字間**：W37の実物はTyberだけ−2%で、ほかは0だった。取り込み時の既定値は0（09-11の決定）のままでよいか。
4. **表紙の帯**：§3.1-5の保守的な自動判定で進めてよいか。それとも手動の指定を先に作るか。
5. **HUG / HUG**：RMのWEEK列が空欄だが、実物には載っている。`掲載`でよいか。
