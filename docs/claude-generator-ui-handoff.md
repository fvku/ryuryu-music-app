## 現在の画面と操作基準

- PCはサムネイル／大プレビュー／編集パネルの3カラム。1280px未満はプレビューを上部にsticky表示する。
- **編集画面（`/generator/<id>`）だけ、アプリ共通のボトムナビ・フッター・`main` の下余白を出さない。** 判定は `lib/app-chrome.ts` の `isImmersiveRoute()` 1か所。ほかの画面の見え方は変えない。この縦はプレビューの大きさに直接効くので、帯を増やすときは大プレビューの実測値と合わせて判断する（2026-09-07に402→522pxへ拡大、ページの縦スクロールは0）。
- 編集パネルのタブは1段で「情報修正／背景設定」。共通設定は`/generator/<id>/settings`へ分けた（2026-09-12）。その手前の行に、画像ごとの状態・編集開始・保存を置く。「画像編集」でひとまとめにする2段目は作らない。並び順はモーダル。
- 出力できない理由は、PNGの出力ボタンと同じ行に出す。**判定条件（文書全体の未保存で止める）は変えない。**
- サムネイルには画像ごとの未保存・他の人の編集中・背景未設定を出す。導出は `derivePageBadges()`（テストあり）。
- プレビューのクリックで作品名、アーティスト、曲数・総尺、ジャンル、国、おすすめ曲番号、おすすめ曲名、評価文を選択できる。評価文はドラッグまたは入力欄内で範囲選択できる。
- **2026-09-12に利用者の決定で変更**：作品と背景は「この画像を編集」を押してから編集する。表示時の自動ロックは行わない。以前の「開始ボタンは置かない」という不変条件はこの決定で置き換えた。ほかの利用者のロック、同一人物の別端末、取得失敗では状態と引き継ぎ／再試行を表示する。
- 別の画像へ移るとき、直していない画像のロックは解放する。未保存があるときだけ、戻れるように残す。見て回っただけで複数対象を占有し続けない。
- 「保存」は画像ごとに1つ。その画像の作品と背景色を順に確定する。内部は従来どおり対象別のPATCHで、ロック・版・履歴の粒度は変えない。自動保存や履歴なしの直接更新へ変えない。
- 保存が途中で失敗したときは、成功した分を確定したまま残す。対象別の競合はその対象だけ失敗として残りを続け、認証の失敗と結果不明（通信断・5xx）はそこで列を止める（v2 §8-2）。
- **2026-09-12に統合**：ヘッダーのボタンは「共有DBを再読込」と「Release Masterから更新」の2つ。前者は共有DBの読み直し、後者はRelease Masterの読み直し。以前の「再取得」（文字情報）と「取り込み直す」（作品の増減）は、1つの差分ダイアログの2つの節になった。**この2つのボタンは1つにまとめない。**読む先が違う。
- 更新の実行順序は、作品の増減を新しいversionとして確定 → 文字情報と取り込み基準を下書きへ、で固定する。逆順にはできない（下書きがあると取り込み直しがDB側で止まるため）。比べる範囲はその画像に描かれる項目だけ。
- 取り込み基準（`item.source`）を進めるのは、利用者が項目を選んだ作品と、カバー画像が変わった作品だけ。手を入れた作品まで黙って進めると、次の更新で差分が出なくなる。
- 共通設定と並び順は現在も明示的な編集開始を使う。UIを統一する場合も、ロック範囲と保存対象を混ぜない。

## 今回の受入で復元・確定した機能（削除・後退させない）

### Timeの読み込み

- 新規文書はRelease MasterのTime列を`duration`へ取り込む。
- 既存versionで`duration`が空の場合は、表示時に最新のRelease MasterをUID、No.、タイトル＋アーティストの順で照合し、空欄だけをローカル下書きへ補完する。
- この補完で共有DBを自動更新しない。利用者が各作品の「保存」を押したときにversionとして確定する。
- 実Monthly文書では空だった11件が補完され、先頭作品で`11songs, 41min 15sec`を確認済み。

### 字間・行送り

- 字間と行送りは数値を直接入力できる。入力途中の空欄・符号・小数点を許容し、有効値は即時プレビューする。
- 既存値を選択中に数字を入力すれば、先に削除しなくても置換できる。ダブルクリックでも数値全体を選択できる。
- Blur／Enter時に許容範囲へクランプする。字間は−20〜20%、本文手動上限は28〜84px、その他の行送りは100〜300%。
- 選択範囲に複数の字間が混在すると、字間欄の値を空にしてplaceholderに`Mixed`を表示する。`Mixed`を文字列の保存値にはしない。
- 字間はUI上で%小数1桁、保存時はem小数3桁へ丸める。保存済みの文字別`kerns`を一括値で意図せず消さない。

### プレビューからのおすすめ曲選択

- おすすめ曲帯を一括で「おすすめ曲番号」扱いにしない。描画と同じ`TextLayout.bandLayout()`が返すpartの`key`、`width`、`gap`、`total`を使い、番号と曲名の実描画位置に最も近い項目を選ぶ。
- 固定文言`RECOMMEND`と区切り文字は編集対象にしない。
- 実画面で`Canyons`をクリックし、調整対象が「おすすめ曲名」へ切り替わることを確認済み。

## 本文行送りの完成済み契約

- レビュー本文は`bodyLeadMode: "auto"`が既定。
- 左右と同じ25pxの余白を天地にも確保する。
- 複数行では先頭行と最終行を有効範囲へ揃え、利用可能な高さまで行送りを最大化する。1行は天地中央。
- 最小行送りは本文文字サイズと同じ28px（1200px基準）。28px未満にしないと収まらない場合は出力不可としてPNG生成を止める。現在の本文枠では14行まで成立し、15行以上は不成立。
- 自動を解除した場合だけ`bodyLeadMode: "custom"`とし、`bodyMaxLead`を28〜84pxで使う。
- `bodyLeadMode`がない旧文書は`auto`として扱う。DB移行は不要。
- UI上の配置や表現は再設計できるが、描画結果、保存・履歴・復元、旧文書との互換性は変更しない。

## 以前のUI変更で失われかけた／Codexが補修した前提

- `body`の横方向overflowは`hidden`ではなく`clip`。`hidden`へ戻すとルートヘッダーを含む`position: sticky`が効かなくなる。
- 画像準備は`image.decode()`だけを待たず、`load`との早い方を採用する。非表示タブ、スリープ、タブ切替で描画が止まるため。
- 保存の通信結果が不明な場合、同じ内容の再試行には同じ`requestId`を使う。成功／明確な4xxまでは捨てない。
- 30秒heartbeatの遅延応答は、現在の`clientId`・`token`・`generation`と一致するときだけロック状態へ反映する。解放・引き継ぎ後の新しいロックを古い応答で上書きしない。
- ローカル復旧は作品本文、背景、共通設定だけでなく保存時点の並び順も戻す。現在の作品ID・ページID・ページ種別が一致しない場合は部分適用せず拒否する。
- 掲載ページの評価文は画像にも調整対象にも出さないが、既存の保存値を失わないよう読み取り専用の一覧には残す。
- PNGは文書全体に未保存がある間は出力不可。別対象だけ未保存でも出力を許す変更は、仕様判断なしに行わない。
- 編集ワークスペースだけ最大1600pxまで広げる。`app/layout.tsx`全体の幅を広げて他画面へ影響させない。
- 現行実装ではiPhoneで字間UIを出さない。判定は`(max-width: 639px)`または`(pointer: coarse) and (max-height: 500px)`。保存済みの`tracking`／`kerns`は描画・保存し続け、非表示を値の削除や初期化に結びつけない。ただし、モバイル版のUIと提供機能は2026-09-09の利用者指示により再検討対象であり、この表示方針自体は不変条件ではない。
- Release Master由来の原稿と利用者が修正した`content`を混同しない。UI表示の都合で`source.fields`を上書きしない。

## 保存・ロックの不変条件

- リクエストの`requestId`、`expectedVersion`、ロックの`clientId`・`token`・`generation`を維持する。
- ロックは対象別（item／page／theme／structure）。異なる対象をまとめて保存しない。
- 保存後も履歴を消さず、復元は選択した過去内容を新しいversionとして書き戻す。
- 画像アップロードは対象の有効なロックが必要で、アップロード後に対象を保存してversionへ確定する。
- ローカル復旧キー`ryuryu_generator_recovery:v1:<actor>:<documentId>`、`schemaVersion: 1`、600msデバウンス、拒否条件を維持する。

詳細は`docs/generator-shared-storage.md`を正とし、UIからAPI payloadを変える場合は必ずCodexへ戻してください。

## ローカル本番プレビュー

Google OAuthのredirect URIを変更せず確認するため、localhost・非Vercel・許可メンバーに限定した認証迂回がある。本番環境では有効にしない。起動条件と安全条件は`docs/generator-shared-storage.md` §3を参照する。

現在確認済みの起動例：

```bash
env AUTH_TRUST_HOST=true \
  AUTH_URL=http://localhost:3456 \
  NEXTAUTH_URL=http://localhost:3456 \
  GENERATOR_LOCAL_PREVIEW_AUTH_BYPASS=true \
  GENERATOR_LOCAL_PREVIEW_ACTOR=kohei.fuku0926@gmail.com \
  node --env-file=.env.development.local node_modules/next/dist/bin/next start -p 3456
```

この迂回は画面を本番モードで確認するためだけのもの。Google認証自体を本番から外したり、迂回用環境変数をVercelへ登録したりしない。

## 変更時の確認項目

最低限、次を実行してください。

```bash
npx tsc --noEmit --incremental false
npm run lint
npm test
npm run build
```

現時点の基準は16テストファイル・276件成功、本番ビルド成功。さらに実ブラウザで次を確認してください。

- Time表示、作品／背景の直接編集、対象切替時の旧ロック解放
- 数値の選択置換と`Mixed`表示
- プレビューから作品名、情報帯、おすすめ曲番号／曲名、評価文を選択
- 14行／15行の出力可否、未保存時のPNGゲート
- PC／iPad／iPhoneのsticky、横スクロール、操作欄とプレビューの同時視認
- consoleの警告・エラー、サムネイルと大プレビューの描画完了

共有DBに変更を残す保存・復元・画像アップロードまでテストする場合は、利用者の依頼範囲を確認する。見た目確認用の変更は保存せず、再読込で破棄する。

機能側へ戻すときは`docs/codex-generator-handoff.md`も現在地に合わせて更新する。commit、push、デプロイ、共有DBの永続変更は依頼されるまで行わない。
