# 画像ジェネレーター：初見でも使える画面への修正方針

2026-09-18作成。対象は編集画面（`/generator/<id>`）。
[UI実装記録 §32](./generator-ui-implementation.md)（画像を選ぶと編集が始まる形）の続きで、
利用者の依頼「初見の人でも使えるUIにしたい」に対し、つまずきそうな点を24件洗い出したうえでの方針。

**API・DB・保存payload・ロックの粒度は変えない。** 変えるのは言葉・表示の場所・部品の並びだけ。
[引き継ぎプロンプト](./claude-generator-ui-handoff.md)の不変条件（「最新版に更新」と「Release Master 再読込」を1つにしない、
未保存でもPNGは書き出せて一言添える、復旧キー・スキーマ、iPhoneで字間を出さない等）は守る。

---

## 1. 基本の考え方

1. **状態を言う場所は3つだけ。** ヘッダー＝文書全体、サムネイル＝画像ごと、編集パネルの帯＝いまの画像。
   それ以外（上部の帯、PNG下の注意、タブの点など）で状態を繰り返さない。
2. **1つの言葉に1つの意味。** 特に「保存」はみんなのデータへの確定だけに使い、画像の書き出しには使わない。
3. **作った側の言葉を画面に出さない。** version、共有DB、ロック、編集権、取り込み基準、復旧用コピーを言い換える。
4. **いつも出ているものは、いつも必要なものだけ。** 異常時だけ要る情報は、異常時だけ出す。

---

## 2. 言葉の置き換え

| いま | 変更後 | 理由 |
| --- | --- | --- |
| 保存（画像ごとの確定） | **保存** | そのまま。この言葉はこの意味専用にする |
| PNGを保存 | **PNGを書き出す** | 「保存」と混同させない（つまずき17）。利用者の指定で「ダウンロード」ではなく「書き出し」 |
| 全ページを書き出す | **全ページを書き出す（ZIP）** | 同上 |
| 共有 | **アプリで送る** | 中身はOSの共有シート（LINE・Instagramなど）へ渡すボタン |
| 2400 × 2400（チップ） | 「2400px」を書き出しボタンの補足へ | 押せそうに見えるチップをやめる |
| 最新版に更新 | **最新のバージョンを読み込む** | 何を読み直すかを言う。1つにはまとめない |
| Release Master 再読込 | **Release Masterから取り込み直す** | 同上 |
| 最終保存 version 13 · Kohei · 9/13 11:44 | **最後の保存：9/13 11:44（Kohei）** | 版番号は「変更履歴」の中だけで使う |
| 共有DBと一致／共有DBに未保存 | 保存済み／未保存 | §32で一部済み。残りを揃える |
| 復旧用コピー | **このブラウザの一時保存** | 「保存済み（共有保存なし）」の矛盾をなくす |
| 編集権・ロック | 「編集中」「編集できません」 | 仕組みではなく、できる・できないで言う |
| 取り込み基準 | 画面に出さない（§3-4） | 利用者が判断する材料ではない |
| 情報修正／背景設定（タブ） | **文字**／**背景色** | 何を直す場所かを言う |
| 出す（チェック） | **画像に表示** | 何に出すのかを言う |
| ↺ ↻ | **元に戻す**／**やり直す**（アイコン＋文字） | アイコンだけにしない |
| 過去版から復元 | **以前の保存に戻す** | 「版」を使わない。何が戻るか（この作品／この画像の背景色）を中に書く |
| 背景色 未設定（色は入っている） | **背景色：候補を仮表示中** | 色が見えているのに「未設定」と言わない。保存で確定することを添える |
| Choose File / No file chosen | **画像ファイルを選ぶ** | ブラウザ標準の英語を出さない |

## 3. 状態表示の整理

### 3-1. ヘッダー（文書全体）

- 「すべて保存済み」／「未保存：画像 1・3・並び順」はそのまま。**画像番号を押すとその画像へ移る**ようにする。
- ヘッダーのボタンは役割で分ける。
  - 読み直し系（最新のバージョンを読み込む／Release Masterから取り込み直す）は「読み込み」メニュー1つに畳む。
    **1つの操作にはまとめない**（読む先が違う）。メニューの中で2つを並べ、それぞれに一行説明を付ける。
  - 「最新のバージョンを読み込む」は、未保存があると黙って捨てていた。**確認を挟む**（保存／変更を破棄／やめる）。
  - 共通設定・変更履歴は控えめな文字リンクへ。主操作は「全ページを書き出す（ZIP）」だけ。

### 3-2. サムネイル（画像ごと）

- 印は **語で出す**（「背」のような1文字略をやめる）：「未保存」「Meri が編集中」「背景色なし」。
- **自分の「編集中」の印はやめる。** いま選んでいる画像は枠で分かる。「編集中」は他の人だけに使う。
- **表紙の「未保存」は、表紙自身の背景色が未保存のときだけ。** 作品の未保存はその作品の画像で数える
  （ヘッダーはすでにこの数え方。サムネイルも揃えて食い違いをなくす。つまずき7）。

### 3-3. 編集パネルの帯（いまの画像）

- §32の帯（✎ 画像 N を編集中／保存状態／変更を破棄・保存）を正とする。
- 他の人の編集を待っている間は「20秒ごとに確認しています」と出し、止まっていないことを見せる。
- 待っている間にプレビューを押したら、帯を一度光らせて「編集できるようになるまで選べません」と出す（いまは無反応）。

### 3-4. 上部の帯（いまの StatusBanner）

いつも黄色で出ていて、重要な警告が埋もれている（つまずき5・6）。**操作の結果だけを出す場所**にする。

| 情報 | 変更後 |
| --- | --- |
| 操作の結果（保存しました等） | 帯に出して数秒で消す。エラーは消さず赤で出し、次にできることを添える |
| このブラウザの一時保存 | 平常時は出さない。**開いたときに前回の一時保存が残っていたときだけ**「前回の保存していない変更が残っています［開く］［捨てる］」と出す |
| 他の人の編集中 | 帯から外す（サムネイルと編集パネルで言う） |
| 取り込み基準 | 帯から外す。Release Masterの取り込み直しダイアログの結果として一度だけ伝える |
| Release MasterのTimeを再取得できませんでした | **Timeが空の作品があるときだけ**出す。いまは空欄が無くても毎回出ている |

### 3-5. プレビューの下

- 未保存でも書き出せる、という決定（2026-09-13）は守る。添える一言は短くし、書き出しボタンの**すぐ横**に置く：
  「保存していない変更も含めて書き出します」。

## 4. 編集パネルの並び

### 4-1. 文字タブ

いまは一番上に「調整対象・字間・行送り」の枠があり、文字を直す入口（小さな✎）が下に埋もれている（つまずき11）。

- **欄の一覧を上に置く。** 各欄は行のどこを押しても入力欄が開く（✎を探させない）。「画像に表示」のチェックは行の右端。
- **字間・行送りは、選んだ欄の直下に開く。** プレビューから選んだときも同じ場所に開く。
  ガイドライン2.4の「仕上げで繰り返す操作は近くに置く」を、上部固定ではなく「選んだものの近く」で満たす。
  - 評価文の範囲選択と`Mixed`表示、数値の直接入力・選択置換は今のまま移す（完成済み機能）。
  - 「元に戻す／やり直す」は字間・行送りの枠の中に、文字付きで置く。
- **状態を枠の色だけで見分けさせない。**
  - 選んでいる欄：左に紫の線＋薄い紫の背景
  - 変えた欄：「変更あり」の文字（黄）。枠は細い黄
  - パネル全体の「編集中」の紫枠は細くし、欄の選択と同じ強さに見えないようにする
- 「（未入力）」の欄には「ここで入力するか、Release Masterを直して取り込み直してください」と一行添える。

### 4-2. 背景色タブ

- 「候補を仮表示中」のときは、候補の並びの上に「この色で保存するか、別の色を選んでください」と書く。

### 4-3. ジャケット

- ファイル選択は日本語のボタン（「画像ファイルを選ぶ」）にする。
- 「Release Master」のチップは「取り込んだ画像」に。差し替えた後は「差し替えた画像」。

---

## 5. 最初の一歩

- 編集画面の上部に、**閉じられる3ステップの案内**を出す：
  ① 画像を選んで確認・修正 → ② 画像ごとに「保存」 → ③ 全ページを書き出す
  閉じたらこのブラウザで覚える（`localStorage`。読めなくても案内が出るだけで壊れない）。
- 「使い方」（ヘッダー右上の既存リンク）からいつでも出し直せるようにする。
- プレビューの縦寸法を削らないよう、1行・閉じるボタン付きの高さに収める（ガイドライン2.1、実寸を測る）。

---

## 6. 任意：未保存をまとめて保存

Time補完やRelease Masterの取り込み直しで、多くの画像に一度に未保存ができる（つまずき20）。
ヘッダーの「未保存：画像 1・3」の横に「**未保存をすべて保存**」を置く案。

- 中身は既存の対象別PATCHを画像ごとに順に呼ぶだけ（v2 §8-2の止め方そのまま）。API変更なし。
- ただし他の画像の背景ロック・作品ロックを一時的に取る必要がある。他の人が編集中の画像は飛ばして、最後に「画像 4 は Meri が編集中のため保存していません」と言う。
- ロックの取り方が増えるので、1〜3の後に別の段として判断する。

---

## 7. スマホ

2026-09-09の利用者指示で、モバイル版は機能範囲から見直す予定がある。今回は最小限にとどめる。

- 画面上部に固定したプレビューの下端に、編集中の帯（画像番号・保存状態・保存ボタン）を細く重ねる。
  いまはプレビューが帯を隠し、編集中かどうかが見えない（つまずき23）。

---

## 8. 進め方

| 段 | 内容 | 規模 | 危険度 |
| --- | --- | --- | --- |
| 1 | 言葉の置き換え（§2）、状態表示の整理（§3） | 中 | 低（見た目と文言。ロック・保存の流れは触らない） |
| 2 | 編集パネルの並び替え（§4） | 中〜大 | 中（範囲選択・`Mixed`・プレビューからの選択など完成済み機能を移すため） |
| 3 | 最初の案内（§5）、スマホの帯（§7） | 小 | 低 |
| 4 | 未保存をまとめて保存（§6） | 中 | 中（ロックの取り方が増える） |

- 段ごとに型チェック・lint・テスト・本番ビルドと、実ブラウザ（PC／iPad幅／iPhone幅）で確認し、UI実装記録へ追記する。
- 共有DBへの保存を伴う確認は、依頼があるときだけ行う。
- 実装は Opus 5／エフォート高 を想定（ロック・保存の不変条件と完成済み機能の保全が多いため）。

## 9. 利用者の決定（2026-09-18）

| 論点 | 決定 |
| --- | --- |
| 言葉 | §2の方針で進める。ただし画像は「ダウンロード」ではなく**「書き出し」**（PNGを書き出す／全ページを書き出す（ZIP）） |
| 読み直しの名前（追加） | 「みんなの最新の保存を読み込む」→**「最新のバージョンを読み込む」** |
| 字間・行送りの位置 | 選んだ欄の直下へ移す |
| 範囲 | 段1〜3（§6「未保存をすべて保存」は今回やらない） |
| 実装 | Opus 5／エフォート高 |
| パネルの形（追加） | タブをやめて1枚（背景色を上に1行、その下に文字）。「変更を破棄」「保存」はパネル下端に貼りつく帯へ（画面の下端に固定。スクロールしても見える）。紫の囲みと枠は廃止 |
