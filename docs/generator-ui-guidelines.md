# 投稿画像ジェネレーター UIガイドライン

更新日：2026-09-08
対象：Monthly／Japan／Weekly 投稿画像ジェネレーターの操作画面

## 1. この文書の位置づけ

この文書は、投稿画像ジェネレーターの情報設計、画面構成、見た目、操作部品、レスポンシブ表示を変更するときの共通基準である。現在の実装と2026-09-07〜08の受入結果をもとに、今後も維持する原則と標準値をまとめる。

機能の挙動は[操作仕様](./generator-specification.md)、保存・ロック・履歴・認証は[共有保存の実装状況](./generator-shared-storage.md)を正とする。個別の変更理由と検証結果は[UI実装記録](./generator-ui-implementation.md)、現在の再開条件は[Claude Code向け引き継ぎ](./claude-generator-ui-handoff.md)を参照する。

内容が食い違う場合は、次の順で判断する。

1. 利用者の最新の明示判断
2. 操作仕様と共有保存の契約
3. このUIガイドライン
4. UI実装記録のうち日付が新しい判断
5. 実コード

実コードと上位の文書が食い違う場合は、コードを正として放置せず、意図を確認してどちらかを更新する。

このガイドが対象にするのは編集アプリのUIである。書き出される投稿画像の書体、罫線、余白、版面は、Monthly／Japanの描画仕様と[Weeklyの設計](./generator-weekly-design.md)で管理する。

## 2. 基本原則

### 2.1 プレビューを主役にする

主な作業は、取り込まれた作品情報を確認し、字間・行送り・表示項目・背景を調整して投稿画像を完成させることである。大きなプレビューを常に判断の中心に置き、調整中も仕上がりを見られる状態を保つ。

説明、状態表示、操作帯を追加するときは、プレビューの表示寸法と同時視認性への影響を実測する。通常のPC表示では、ページ全体をスクロールせずにプレビューと主操作が見える状態を目標にする。

### 2.2 操作の作用範囲を見せる

利用者が「どの画像の、どの対象を、どの範囲まで編集しているか」を判断できるようにする。作品、背景、共通設定、並び順は保存とロックの単位が異なるため、画面上でも混ぜない。

保存、復元、編集終了、PNG出力には、作用する対象が分かる位置と文言を使う。ページ単位の操作と文書全体の操作は、同じ操作群に見えないよう配置を分ける。

### 2.3 状態を色だけで伝えない

共有保存済み、未保存、ブラウザ内の復旧用コピー、他の人が編集中、通信エラー、出力不可を区別する。色は意味の補助として使い、短い文言またはラベルを併記する。

操作できない場合は、その操作の近くに理由を表示する。ボタンの無効化だけ、薄い表示だけ、マウスを重ねたときだけの説明には依存しない。

### 2.4 頻度に合わせて情報を開く

字間・行送り・取り消し・やり直しなど、仕上げで繰り返す操作は常に近くに置く。Release Master由来で修正頻度が低い文字情報は、現在値を先に見せ、修正するときだけ入力欄を開く。

プレビューと文字要素一覧のどちらから選んでも、同じ調整対象につながるようにする。並び替えのように独立して完結する操作はモーダルで扱い、編集パネルの常設タブを増やさない。

## 3. 画面構成

### 3.1 編集ワークスペース

- 1280px以上は、ページ一覧／大プレビュー／編集パネルの3カラムとする。
- 1024〜1279pxは、大プレビュー／編集パネルの2カラムを基本とし、ページ一覧は横方向へ置く。
- 1024px未満は縦に並べ、プレビューを画面上部にsticky表示する。
- 編集ワークスペースだけ最大1600pxまで広げる。他画面の幅は連動して広げない。
- `/generator/<id>`では、アプリ共通のボトムナビ、フッター、過剰な下余白を表示しない。

編集パネルの最上段は「情報修正／背景設定／共通設定」の1段とする。次の行に、現在の対象の状態、保存、復元を置く。「画像編集」のような上位タブを追加して2段構造へ戻さない。

掲載ページで上段・下段を切り替える操作は、情報修正の中だけに表示する。ページの並び順はモーダルで変更する。

### 3.2 プレビュー

プレビューには、現在の画像番号とページ種別を添える。選択中の文字要素や評価文の範囲は、Canvasの上に操作用の表示として重ね、PNGや共有保存データへ含めない。

出力不可の理由は「PNGを保存」の近くに表示する。全ページの書き出しは文書単位の操作として、ページ単位の「PNGを保存」「共有」と配置を分ける。

### 3.3 ページ一覧

選択中の画像を枠と文字色で示す。各サムネイルには、必要に応じて未保存、他の人が編集中、背景未設定を表示する。9〜10pxの表示はサムネイル内の短い補助バッジに限り、操作判断に必要な情報をその大きさだけで伝えない。

## 4. 文字の階層

操作画面の基本書体は、アプリ共通のsystem-uiを使う。投稿画像内の書体とは分けて扱う。

| 用途 | 標準サイズ | 基準 |
| --- | ---: | --- |
| 画面タイトル | 16〜18px | 企画名など現在地を示す |
| パネル見出し・主要な表示値 | 14px | 編集領域と作品情報の見出し |
| 入力値 | 16px | 数値・文字入力の読みやすさを維持する |
| 操作ラベル・通常の補足 | 12px | ボタン、項目名、短い説明 |
| 状態バッジ・付随情報 | 11px | 更新情報、短い状態、補助ラベル |
| サムネイル内の補助バッジ | 9〜10px | 狭い領域だけに認める例外 |

入力欄は周囲をコンパクトにした場合も16pxを基本とする。長い説明は短くするか、詳細を開く形にする。文字サイズを下げるのは最後の手段とする。

見出しだけ、色だけ、太さだけで複雑な階層を増やさない。画面内では「現在地」「編集対象」「操作」「補足」の順が読み取れるようにする。

## 5. 操作部品のサイズ

| 部品 | 標準 | コンパクト |
| --- | --- | --- |
| ボタン | 高さ44px以上、14px | 高さ36px以上、12px |
| 1行入力欄・セレクト | 高さ44px以上、16px | 原則として標準を維持 |
| タブ | 14px、上下8px | 12px、上下6px |
| パネル内余白 | 16〜20px | 12px |
| 状態表示の帯 | 14px、上下12px | 11〜12px、上下6px |

標準は、企画作成、通常の入力フォーム、モーダル、単独の主要操作に使う。コンパクト表示は、プレビューの面積に直接影響する編集画面上部、対象別の状態・保存、密度の高いデスクトップ編集パネルに使う。

同じ列に並ぶボタンは、高さ、文字サイズ、角丸をそろえる。主操作の重要度は色と配置で示し、同じ操作群の中で不必要に大きさを変えない。

タッチ端末では、見た目が小さいアイコンやチェックボックスも、ラベルや周囲を含む押せる領域を原則44px程度確保する。デスクトップ専用の密な操作では36pxを認める。

## 6. 余白と形

余白は4px刻みを基本とする。

| 間隔 | 主な用途 |
| ---: | --- |
| 4px | ラベルと値など、強く関連する情報 |
| 8px | 同じ操作群、一覧項目内 |
| 12px | 編集パネル内の小さなグループ |
| 16px | パネル間、画面内の主要な区切り |
| 20〜24px | モーダル、独立した領域の内余白 |

角丸は次を基準にする。

- 入力欄、一覧項目：8px
- ボタン、タブ、状態表示：12px
- パネル、モーダル：16px
- 短い状態バッジ：完全な丸型

余白を詰める場合も、作用範囲が違う操作の区切りは残す。エラーや長い作品名が加わったときの折り返しを考え、通常状態だけを基準に高さを固定しない。

## 7. 色

| 役割 | 基準色 |
| --- | --- |
| 画面背景 | `#0f0f13` |
| パネル背景 | `#1a1a24` |
| パネルのhover | `#22223a` |
| 主要な文字 | `#ffffff` |
| 補助的な文字 | `#9ca3af` |
| 選択・主操作 | `#8b5cf6` |
| 主操作のhover | `#7c3aed` |
| 薄い境界線 | `rgba(255, 255, 255, 0.08)` |
| 選択を伴う境界線 | `rgba(139, 92, 246, 0.4)` |

紫は選択状態と主操作に使う。成功は緑、注意と未保存は黄、エラーと失敗は赤を使う。評価文の選択範囲を示す青は、文字範囲の操作表示に限定する。

無効な主操作は存在とラベルが読める濃さを保つ。特に暗い背景では、部品全体を一律に低いopacityへ落とさず、背景、文字、補足ラベルを個別に調整する。

色は`app/globals.css`のCSS変数と`app/generator/ui.tsx`の共通部品から使う。新しい意味色を各画面へ直接増やす場合は、既存のinfo／success／warn／errorで表現できない理由を確認する。

## 8. 共通部品

新しい画面や操作は、まず`app/generator/ui.tsx`の部品を使う。

- `Panel`：独立した編集領域。通常と密な編集画面で余白を切り替える。
- `SegmentedControl`：同じ場所の内容を切り替える。未保存や編集中は小さな点で補助する。
- `PrimaryButton`：保存、確定、生成など、その操作群の主操作。
- `SecondaryButton`：再読込、取消、編集終了などの補助操作。
- `StatusBanner`：操作結果、通信状態、警告。編集画面ではdenseを使える。
- `Chip`：対象の状態を1語程度で示す。説明文の代わりには使わない。
- `Field`と入力部品：ラベル、入力、必要な補足をひとまとまりにする。
- `Modal`：並び順など、現在の画面の上で完結する作業。

共通部品の見た目を局所的なclassで上書きするときは、同じ操作群との整列、タッチ領域、レスポンシブ表示を確認する。複数箇所で同じ上書きが必要になった場合は、共通部品のvariantとして扱う。

## 9. 状態とフィードバック

状態表示は「対象」「状態」「次にできること」の順で理解できる文にする。

- 未保存：どの対象に変更があるかを示す。
- 共有保存済み：対象別の保存が完了したことを示す。
- 復旧用コピー：ブラウザ内だけの保存であり、共有保存ではないことを併記する。
- 他の人が編集中：編集者を示し、閲覧できる状態は維持する。
- 同じ人の別端末：引き継ぎ操作を表示する。
- 通信失敗：再試行できる操作と、結果が不明か明確に失敗したかを区別する。
- 出力不可：該当する画像番号と解消方法を、出力操作の近くに示す。

短時間の処理にはボタン内または近くの状態表示を使う。全ページ書き出しのように時間がかかる処理では、進捗と中止を同じ場所に表示する。処理中に操作名を頻繁に変えて位置を揺らさない。

## 10. 編集と選択

文字要素の行全体を選択面とし、現在値を見ながら対象を切り替えられるようにする。文字そのものを直す操作は、調整対象の選択と区別する。

プレビューでは、作品名、アーティスト、曲数・総尺、ジャンル、国、おすすめ曲番号、おすすめ曲名、評価文を実際の描画位置から選べるようにする。固定文言と区切り記号は編集対象にしない。

評価文の文字範囲は、字間欄や行送り欄へ移動しても、入力値をプレビューへ反映しても維持する。Enter、「調整を確定」、別の文字欄への移動、編集領域外への移動で解除する。`Mixed`は複数の字間が含まれる表示状態であり、保存値として扱わない。

表示チェックを外しても入力値は保持する。掲載画像に描画しない評価文も、既存の保存値を失わないよう読み取り専用で残す。

## 11. レスポンシブとタッチ

狭い画面では、要素を縮小し続けず、折り返し、縦並び、横スクロール可能なタブやページ一覧へ切り替える。ページ全体に意図しない横スクロールを作らない。

プレビューは1280px未満でsticky表示を基本とし、入力中も仕上がりと調整欄を行き来しやすくする。`body`の`overflow-x`は、stickyを壊さない`clip`を維持する。

iPhoneでは字間調整を表示しない。判定は`(max-width: 639px)`、または`(pointer: coarse) and (max-height: 500px)`とする。行送りは操作でき、保存済みの`tracking`と文字別`kerns`は描画・保存し続ける。

タッチ操作ではCanvas上のドラッグを奪わず、ページスクロールを維持する。タップによる対象選択と、入力欄内のネイティブな文字選択を使う。

## 12. 文言

ボタンは、押した結果が分かる動詞を使う。「保存」は現在の対象、「全ページを書き出す」は文書全体というように、作用範囲を周囲の見出しと組み合わせて明確にする。

状態文は、内部実装の用語より利用者が次の行動を判断できる表現を優先する。エラーでは、起きたことに加えて、再試行、保存、文字数の調整など具体的な選択肢を示す。

補足は一度に一つの判断を伝える。常時必要でない長い説明はdetailsやヘルプへ移す。重要な制約はtitle属性だけに置かない。

## 13. コンパクト表示を使う条件

次の条件を満たす場所でコンパクト表示を使う。

- プレビューを大きく保つなど、詰める目的が明確である。
- 操作名、選択対象、保存状態を読み取れる。
- 隣の操作を誤って押しにくい。
- 狭い画面で折り返しまたは配置変更ができる。
- エラー、長い作品名、文字拡大が加わっても必要な情報へアクセスできる。

画面を通常状態で1画面内に収めることは目標とするが、エラー表示、OSの文字拡大、ソフトウェアキーボードによって必要になる縦スクロールは許容する。

## 14. 変更時の確認

UIを変更するときは、少なくとも次を確認する。

- PC、iPad横、iPad縦、iPhoneでプレビューと主操作へ到達できる。
- ページ全体に横スクロールがない。
- sticky、モーダル、各カラム内のスクロールが競合しない。
- 通常、未保存、他者編集中、通信失敗、出力不可の各状態が理解できる。
- 長い作品名、日本語と英語の混在、`Mixed`、14行／15行の境界で表示が破綻しない。
- キーボードだけでタブ、入力、ボタン、モーダルを操作でき、フォーカスが見える。
- 共通部品への局所的な上書きが、同じ操作群の高さと位置を崩していない。
- UI変更が保存、ロック、履歴、復元、PNG出力の契約を変えていない。

一般化できる新しい判断はこの文書へ反映する。個別変更の理由、実測値、検証結果は`generator-ui-implementation.md`へ記録する。
